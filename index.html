结论 1

它是类型图标，不是说话人

在这个位置放拟人头像会和另外 5 个类型图标抢语义——用户会以为「这是一种叫『人』的卡片」。所以 Edward 说的「活人感」放这儿是放错位置，不是画得不够好。

Edward：「它不是个【人类会用的头像】，它是个系统标志。」——它确实就是系统标志，因为这一列全是系统标志。

结论 2

真正该有头像的那段，反而裸着

用户问「How about my toe-side on run 2?」之后，Chatbot 的回答是整段纯文字，没气泡、没头像、没名字。这才是「对话」发生的地方，也是唯一值得放脸的地方。

现在的状态是反过来的：卡片有图标，人说话没头像。

3 · 第三个岗位：教练模式的三个图标

Edward 圈的没错——这三个图标现在确实一样。但结论不是「删掉」，而是「它们本来就该长得不一样」。 这三个模式的差别是教练说多少话，这是个音量概念，用音量三态最直白，20px 下不用数、不用学。

现状

同一个剪影，靠数波浪线区分

深度 / 随行 / 静音三个图标共用一个人头剪影，差别只有右上角一两根小波纹和一个 x。20px 下这点差别等于没有。

Intensive CoachContinuous presence with proactive check-ins.
Standard CoachContinuous monitoring with targeted guidance.
MuteSilent background logging, zero interruptions.

而且这个剪影就是被当成头像误读的那个东西。它在这里表状态，在卡片里表类型，在顶部表模式——一个符号扛不动三种语义。

建议 · 音量三态

形状 + 颜色双重区分，不靠数数

沿用 iOS 音量图标的通用语义：说得多 = 两道声弧，说得少 = 一道，静音 = 划掉并转灰。灰色在这里第一次有了意义——它真的是关掉的。

简洁　Brief只说关键问题，一句话说清
静音　Silent全程不出声，练完自己看

顶部指示器同一套符号，20px 实际尺寸：

列表是用户学会这套符号的地方，顶部是他用它的地方。所以列表里的图标不该删——删了顶部那个就没人认识了。

为什么顶部要留

Mute 是需要被一眼看见的状态

用户滑到一半发现教练一直不说话，第一反应是「坏了」而不是「我开了静音」。顶部一个划掉的灰图标，比读「Mute」两个字快得多。

现在有三套名字在跑

命名得先收敛成一套

设计稿是 Intensive / Standard / Mute（深度 / 随行 / 静音），Susan 文档是 Detailed / Essential / Quiet Observer（深度教练 / 关键提醒 / 勿扰记录），Edward 提的是静音 / 简洁 / 详细。

建议按 Edward 那套收敛——最短、在同一根轴上、顶部 chip 装得下。具体见下一节。

品牌规范

输入框写成了 HeyGo

占位符是「Ask HeyGo Coach…」，但品牌规范是 Heygo（中间 g 小写）。同一屏里 Heygo IQ 是对的，这里不一致，一起改掉。

4 · 三个模式的名字和描述文案

Edward 之前说「文案都去掉，做简单一点」，现在的问题是：【静音】不用解释，【简洁】【详细】不解释看不懂； 只给两个加描述，UI 又不齐。解法是三行都给，但每行压到 11–13 个字——不是段落，是一行标签。

先修一个命名 bug

「简单 / 频繁」混了两个维度

简单说的是「说得少」，频繁说的是「说得勤」——一个讲量，一个讲频率，并排放用户没法比较。三个选项必须在同一根轴上。

这根轴就是教练说多少话。Edward 自己提的那组正好在同一根轴上，直接用：

详细说得最多 简洁说得少 静音不说

Susan 定义里的「深度教练 / 关键提醒 / 勿扰记录」信息是对的，但名字太长——顶部指示器是个小 chip，装不下 6 个字。两个字最合适。

建议文案

三行等长，静音那行也有信息

模式中文描述
详细 每个问题都说，并告诉你怎么改
简洁 只说关键问题，一句话说清
静音 全程不出声，练完自己看
ENEnglish copy
Detailed Calls out every issue and how to fix it
Brief Key issues only, one line each
Silent Never speaks — review it after your run

静音那行不是为了凑格式。它回答的是用户真正会问的那个问题——「静音了还记不记录？」。 所以三行都有信息，UI 也齐了，两个问题一起解决。

写法规则

三行必须同结构

都是「说什么，怎么说 / 什么时候看」两段式，逗号分隔，11–13 字。用户扫一眼就能横向比，不用逐条读完。

别写的东西

不要写「全程」「巴拉巴拉」

三个模式都是全程生效，「全程」是共有属性，写了等于没写（静音那行留着是因为要和「不出声」连读）。也不要写实现细节，用户只关心耳朵里听到什么。

顺带

顶部 chip 只放名字

描述只在 Select Mode 列表里出现。顶部指示器就两个字 + 音量图标，别把描述也带上去。

7 · 落地：本期 6 件事，以后 1 件事

关键是把三个槽位在组件层分开：cardType 管卡片类型，coachMode 管教练音量，speaker 管说话人。分开之后，加不加头像就再也不用重开这个会。

// 三个槽位，语义完全不同，谁也别借谁的图标
enum CardType   { peak, fall, crushed, day, run, voice }
enum CoachMode  { intensive, standard, mute }
enum SpeakerTag { none, name, mark, character }

CoachCard(
  cardType: CardType.voice,     // 薄荷底 + 耳机（类型）
  speaker : SpeakerTag.name,      // 本期：只显示「Coach」
)
ModeChip(mode: CoachMode.mute)   // 音量三态（状态）
